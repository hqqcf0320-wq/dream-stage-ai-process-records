# 《醒来之前》执行计划

目标：完成可运行、可排练的v0.1，保留真实演员最终演出边界与每人动作归因。分支 codex/before-waking-prototype。

## 里程碑

- [x] M1 制作工具和可编辑资产：Blender Python环境，红窗、青绿石板桌椅、小熊/大熊、简化真人占位；导出.blend/.glb。
- [x] M2 实时预演：完整六节点感官路径、雨/金光/暖光、房间旋转退远、熊交换/照顾占位。
- [x] M3 演出控制：四位独立观众输入，贡献记录、演员GO/HOLD/拒绝，热烈/安静两条模拟轨迹，舞台平面视角。
- [x] M4 真实AI接续：服务器调用结构化模型，绑定来源事件和段落版本；人工接纳；迟到丢弃、失败保留规则版本。默认不持续调用。
- [x] M5 验证：完整流程、多人归因、暂停/重置/迟到候选、实际浏览器画面、资产完整性；输出使用说明与限制。

## 实现方式

Blender用官方bpy包生成可编辑资产。由于本机集显与尚未取得学校工作站，第一版用Three.js承载同一GLB的轻量实时排练；这次必须有Blender资产母版、独立事件模型与Unreal导入/控制契约，不能把纯网页技术冒充UE交付。UE原生工程和场地投影校准作为后续目标，不宣称本轮已经验证。

AI通过服务端OpenAI API读取匿名动作事件，产生给演员的具体共振提议；用户的环境中存在可用API凭证，仅服务端使用，不写入文件或浏览器。无AI模式仍能完整演出。动作细节的自由文本是操作员观测输入，不宣称摄像头已识别。

舞台中姥爷的数字形体为站位/动作预演替身，正式由真人扮演。不做数字肖像复刻。升降台只模拟显露；不连接实体机械。

验收：至少两条不同参与路径能抵达交换与照顾；每个事件保留参与者来源；AI接纳能触发局部回调并产生演员可读建议；原型未宣称心理疗效或自动读心。真实舞台效果仍需真人与场地验证。

交付验证见 `prototype-validation.md`；启动与排练方式见 `../prototype/README.md`。本goal的v0.1已交付，真人小规模试演与UE原生工程是下一阶段。
